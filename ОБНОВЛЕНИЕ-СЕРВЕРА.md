# Обновление РУСПЭТ из GitHub

Облачный Codex вносит изменения в приватный репозиторий `CheyMay/ruspet-control`. Рабочая ветка `pilot/november-13`. Перед выкладкой убедитесь, что нужный коммит уже в этой ветке.

Войдите по SSH на рабочий VPS `194.226.98.113` (порт 22). Из консоли под root выполните.

```bash
GIT_SSH_COMMAND='ssh -i /root/.ssh/ruspet_github -o IdentitiesOnly=yes -o BatchMode=yes' git -C /root/ruspet-code fetch origin pilot/november-13
git -C /root/ruspet-code show FETCH_HEAD:scripts/update-server.sh > /root/update-ruspet.sh
bash /root/update-ruspet.sh --apply
```

Чтобы поставить конкретный коммит, укажите полный SHA.

```bash
RUSPET_UPDATE_REVISION=ПОЛНЫЙ_SHA bash /root/update-ruspet.sh --apply
```

`--prepare` проверяет сборку. `--apply` ставит выпуск, запускает миграции при изменении схемы и проверяет сайт и службы. При совпадении `package.json` и `package-lock.json` сборка использует установленные зависимости. При сбое переключения скрипт возвращает предыдущий выпуск. Временные файлы удаляются после успешной установки, подготовки или автоматического отката. Если автоматический откат прервётся, скрипт покажет каталог для восстановления.

Обновления кода выполняются без отдельного дампа на каждый выпуск. Резервные копии PostgreSQL создаются по отдельному расписанию. Для миграций, меняющих или удаляющих рабочие данные, заранее согласуйте совместимость и восстановление.

Чтобы вернуть код и сборку к более раннему коммиту из истории пилота, выполните команду. Схема и содержимое БД остаются на текущей версии, поэтому выбирайте совместимый коммит.

```bash
bash /root/update-ruspet.sh --rollback ПОЛНЫЙ_SHA
```

Для проверки диска и разовой очистки старых сборок выполните следующие команды. `--prune-builds` удаляет сборки и зависимости в старых каталогах `git-release.*`.

```bash
df -h / /opt/ruspet /root
df -i /
nice -n 10 du -xhd1 /root/ruspet-launch /var/backups 2>/dev/null | sort -h | tail -20
bash /root/update-ruspet.sh --prune-builds
```

Проверка после выкладки.

```bash
curl -fsS https://ruspetdev.ru/api/health
systemctl is-active ruspet.service ruspet-bot-proxy.service
cat /opt/ruspet/.voice-tasks-release
```

Рабочие настройки и ключи хранятся на сервере. Telegram обслуживает один процесс. Для разбора ошибки сохраните SHA и первую ошибку из вывода.
