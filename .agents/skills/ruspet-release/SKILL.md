# РУСПЭТ

- Рабочая ветка `pilot/november-13` приватного репозитория `CheyMay/ruspet-control`. Начинай с `AGENTS.md` и [состояния проекта](../../../СОСТОЯНИЕ-РУСПЭТ.md). Сверяй ветку и SHA перед правками. Если работа идёт в PR, сообщи, какой коммит нужно слить в рабочую ветку.
- Запускай проверки по одной. Для изменений API или БД используй изолированные фикстуры. Для интерфейса собери `GOMAXPROCS=1 npm run build`. Отправь код и нужные миграции в GitHub. В итоговом сообщении укажи ветку, полный SHA и результат проверок.
- Из облака доводи изменения до GitHub. Выкладку делает оператор на VPS по [инструкции](../../../ОБНОВЛЕНИЕ-СЕРВЕРА.md). Не выдавай коммит в GitHub за установленный выпуск.
- Рабочий каталог VPS `/opt/ruspet`. Git-копия `/root/ruspet-code`, БД `ruspet_demo` и `ruspet_okb`, службы `ruspet.service` и `ruspet-bot-proxy.service`. Установка сохраняет рабочие настройки, ключи и состояние обмена. На VPS нельзя запускать сидирование или повторный импорт как часть обновления.
- Изменения Битрикс24 сверяй с [руководством по подключению](../../../БИТРИКС-ПОДКЛЮЧЕНИЕ.md). Для чтения и записи используется согласованный балансировщик. Секреты хранятся на сервере. Массовая синхронизация и реальная запись требуют отдельного согласованного прогона.
