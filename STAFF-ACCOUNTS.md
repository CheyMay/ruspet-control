# Персональные входы сотрудников

Ветка `feature/staff-accounts`. Входы привязаны к существующим профилям, а не к новым вымышленным людям. Роль, иерархия, задачи, пароли и привязки Telegram существующих пользователей сохраняются. Число 10 — целевое минимальное количество пользователей с активным веб-входом, не ограничение системы. Несколько логинов одного человека считаются одним пользователем.

## Через панель

Администратор открывает «Настройки → Доступы сотрудников» и нажимает «Создать вход» у нужного человека. Можно изменить предложенный логин. Пароль генерируется случайно и показывается один раз; скопируйте его и передайте лично сотруднику. Общий список хранит только логины и статус. Директору и менеджерам создание входов недоступно.

Если у сотрудника уже есть аккаунт, включая отключённый, новый вход не создаётся. Эта операция не сбрасывает пароли и не восстанавливает отключённый доступ. При утрате показанного пароля требуется отдельный сброс администратором; извлечь пароль из хеша нельзя. Если ответ создания потерялся, обновите список перед повтором.

## Довести общее количество до 10

После установки этого кода на VPS выполните команды **из `/opt/ruspet`, с тем же подключением PostgreSQL, которое использует панель**. `.env` читается автоматически. Не запускайте импорт или миграции ради создания входов: новая схема БД этому выпуску не нужна.

Сначала создать закрытый каталог и посмотреть список кандидатов:

```bash
cd /opt/ruspet
install -d -m 700 -o ruspet -g ruspet /opt/ruspet/.access
runuser -u ruspet -- npx tsx scripts/provision-accounts.ts --total 10
```

Это только план, без паролей и изменений БД. В стандартной установке с двумя действующими входами добавятся восемь сотрудников с задачами. Если начальные администратор/директор ещё не имеют аккаунтов, сначала учитываются они. Сотрудники подбираются по числу назначенных задач, затем по ID; отключённые аккаунты пропускаются. Недостаток кандидатов или занятый логин останавливает весь пакет до изменений. Конкретных других людей можно выбрать вручную в панели.

Для создания используйте **новое имя файла**:

```bash
runuser -u ruspet -- npx tsx scripts/provision-accounts.ts \
  --total 10 --apply --output /opt/ruspet/.access/staff-10.txt
```

В файле с правами `600` будут имя, ID, роль, логин и пароль только новых входов. Пароли не печатаются в терминал и не попадают в журнал действий. Не отправляйте общий файл сотрудникам: каждому передавайте только его доступы. Не помещайте файл в Git или чат.

Сохранение файла и вставки аккаунтов связаны транзакцией: ошибка записи отменяет весь пакет. После сетевой ошибки подтверждение транзакции может быть неизвестно — сохраните появившийся файл и сверьте список входов перед повтором. Повторное успешное выполнение при уже достигнутых 10 пользователях ничего не меняет и не перезаписывает файл. Старый режим скрипта с единственным позиционным путём заменён явными параметрами; существующие пароли больше не сбрасываются при запуске.

Для проверки новых входов без изменения задач:

```bash
runuser -u ruspet -- npx tsx scripts/verify-production-login.ts \
  /opt/ruspet/.access/staff-10.txt
```

Проверка поддерживает новые и прежние файлы admin/director, сверяет пользователя/роль и завершает созданные проверочные сессии. Пароли не выводятся. Привязка Telegram по-прежнему выполняется отдельным приглашением.

## Проверки разработки

Тесты создают свою временную БД с вымышленными пользователями. Проверяются десять разных пользователей, реальные HTTP-входы, права менеджера, сохранение существующих хешей, отключённые аккаунты, откат при ошибке файла, параллельные повторы и отсутствие паролей в журнале/списке доступов. Создание этих фикстур не создаёт аккаунты на VPS.
