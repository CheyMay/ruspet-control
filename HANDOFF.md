# Продолжение работы на другом компьютере

Для разработки без зависимости от домашнего ПК см. [CLOUD.md](CLOUD.md): настройка приватной среды Codex Cloud и отдельной БД разработки. Облачный запуск требует отдельной проверки.

## Быстрый запуск

1. Клонировать закрытый репозиторий под своим GitHub-аккаунтом.
2. Открыть папку репозитория как проект в Codex. Для продолжения написать: «Продолжи РУСПЭТ; сначала прочитай AGENTS.md, HANDOFF.md и README.md».
3. Нужны Git и Node.js 22.12+; на исходном ПК использовался Node.js 24.
4. Выполнить последовательно:

```powershell
npm ci
npm run build
npm run dev
```

Открыть http://127.0.0.1:4310. На Windows можно запустить `START.cmd`.

Первый запуск создаёт локальную PostgreSQL на порту 55439, применяет миграции и загружает 497 задач из `data/first-sheet.json`. Docker не требуется. Повторный запуск не перезаписывает задачи. После изменения зависимостей повторить `npm ci`; после изменения интерфейса — сборку; после изменения API — перезапуск.

## Что переносится через Git

Код React/TypeScript и Node/TypeScript, миграции, инструкции, тесты, исходные значения первого листа Excel. Исходная книга не нужна для первого запуска: её 38 полей сохранены в JSON. Репозиторий приватный, данные реальные.

Git **не переносит текущее состояние PostgreSQL**: отчёты, введённые ответы, новые решения, настройки расписания, привязку бота и сессии. Новая установка восстанавливает исходную выгрузку, а не точную копию действующей базы ПК. Для общей рабочей базы или её точного переноса нужен отдельный защищённый перенос/сервер. Папку работающего кластера PostgreSQL нельзя синхронизировать через Git или обычное облачное зеркало.

Токен Telegram и пароль БД остаются только на исходном компьютере. В свежей базе Telegram и расписание выключены. Для разработки интерфейса доступен раздел «Рабочий бот»: он использует те же сценарии, но не требует Telegram-токена. Предпросмотр меняет локальные задачи — это не отдельный набор фикстур.

## Текущее состояние

- 497 реальных задач, 17 людей из выгрузки, 4 явно тестовые управленческие роли. Реальные назначения руководителей и филиалов в файле отсутствуют.
- Дашборд с непересекающимися очередями: прошлые просрочки, сегодня, впереди, без срока, приёмка, завершённые. Отдельно пересекающиеся признаки и плановая нагрузка.
- Очередь «Нужно действие», возраст ожиданий, роли и ограничения доступа.
- Создание/редактирование задач, сдача, возврат, повторные сдачи, приёмка, согласование сроков; полная история и защита от повторного применения.
- Снимки отчётов, сравнение, автоматизация 09:00/18:00 МСК, архив, CSV и печатная HTML-версия для PDF через браузер.
- Личный Telegram-пилот: меню, задачи, ответы по шагам, решения, история и сводки. Один привязанный чат, текст и ссылки. Реальная загрузка файлов ещё не реализована.
- Проверены TypeScript, сборка и 28 автоматических сценариев. Тесты создают и удаляют собственную отдельную БД; PostgreSQL должна работать. Запуск `npm test` последовательно.

## Открытые вопросы

1. Получить старый лист `taskIndex` для счётчика и прошлых причин переносов. В первом листе Excel этих сведений нет. Текущий `transfer_count` считает только изменения после импорта.
2. Назначить настоящих руководителей, маршруты, филиалы, правила замещения. Обычная приёмка пока работает по существующим правам постановщика/руководителя; старый API маршрутного закрытия сохранён.
3. Дальше развивать Telegram как рабочее место сотрудника, панель — как управление для руководителей. Приоритет: информативно, быстро, минимум лишних действий.
4. Серверное размещение, производственный вход, резервные копии/восстановление, файлы в боте и массовое подключение сотрудников — ещё не выполнены. Демонстрационный сервер слушает только loopback.
5. Полный прежний HTML-прототип и второе ТЗ не были доступны. Интерфейс не заявляется точной копией референса.

## Где что находится

`web/` — интерфейс; `shared/` — общие очереди, аналитика и типы; `server/service.ts` и `workflow.ts` — бизнес-операции; `server/bot.ts` — общий сценарий бота; `server/telegram-pilot.ts` — реальный транспорт; `server/telegram.ts` — старый неиспользуемый прототип; `server/automation.ts` — расписание; `server/migrations/` — БД; `scripts/import-source.ts` — импорт; `tests/` — изолированные сценарии. `LEGACY-AND-OPERATIONS.md` — карта исследования GAS.

Новые изменения коммитить и отправлять в Git; перед работой на другом компьютере получать актуальные изменения. Не редактировать одну ветку одновременно на двух компьютерах без согласования.
