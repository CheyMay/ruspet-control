## Быстрый запуск

1. Клонировать закрытый репозиторий под своим GitHub-аккаунтом.
2. Открыть папку репозитория как проект в Codex. Для продолжения написать: «Продолжи РУСПЭТ; сначала прочитай AGENTS.md, HANDOFF.md и README.md».
3. Нужны Git и Node.js 22.12+; на исходном ПК использовался Node.js 24.
4. Выполнить последовательно:

```powershell
npm ci
npm run build
npm run dev
```

Открыть http://127.0.0.1:4310. На Windows можно запустить `START.cmd`.

Первый запуск создаёт локальную PostgreSQL на порту 55439, применяет миграции и загружает 497 задач из `data/first-sheet.json`. Docker не требуется. Повторный запуск не перезаписывает задачи. После изменения зависимостей повторить `npm ci`; после изменения интерфейса — сборку; после изменения API — перезапуск.

## Что переносится через Git

Код React/TypeScript и Node/TypeScript, миграции, инструкции, тесты, исходные значения первого листа Excel. Исходная книга не нужна для первого запуска: её 38 полей сохранены в JSON. Репозиторий приватный, данные реальные.

Git **не переносит текущее состояние PostgreSQL**: отчёты, введённые ответы, новые решения, настройки расписания, привязку бота и сессии. Новая установка восстанавливает исходную выгрузку, а не точную копию действующей базы ПК. Для общей рабочей базы или её точного переноса нужен отдельный защищённый перенос/сервер. Папку работающего кластера PostgreSQL нельзя синхронизировать через Git или обычное облачное зеркало.

Токен Telegram и пароль БД остаются только на исходном компьютере. В свежей базе Telegram и расписание выключены. Для разработки интерфейса доступен раздел «Рабочий бот»: он использует те же сценарии, но не требует Telegram-токена. Предпросмотр меняет локальные задачи — это не отдельный набор фикстур.
