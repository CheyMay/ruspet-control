# Выпуск с прокси, контрольными отметками и отменой

Нужен одинаковый код панели и бота, миграции 008–011 и зависимости из lockfile. Тесты создают отдельную БД. Не запускать повторный импорт и не подменять рабочую базу фикстурами.

Для Telegram поддержан HTTPS-мост с заголовком `X-Proxy-Secret`: JSON содержит `url`, `method` и объект `body` со всеми параметрами Bot API (`text`, `chat_id`, `reply_markup`, `offset` и т. д.). Для совместимости эти параметры также продублированы на верхнем уровне. На действующем мосте 6 ноября проверка getChat дала 400 для flat и 200 для with_body; только плоский JSON не подходит. Multipart сохраняет прежние отдельные поля и файл; его контракт этим исправлением не меняется. Настройки: `TELEGRAM_PROXY_URL`, `TELEGRAM_PROXY_SECRET_FILE`, `TELEGRAM_BOT_TOKEN_FILE`. Секреты хранить в файлах пользователя приложения с правами 0600 вне Git. Проверка `npx tsx scripts/check-telegram-transport.ts` вызывает только getMe/getWebhookInfo; сообщения не отправляет. Эти методы не проверяют передачу обязательных параметров через мост: успешный preflight сам по себе не доказывает исправность отправки. Автоматического обхода моста и повтора неизвестной отправки нет.

Перед миграцией остановить прежний зарубежный worker и российскую панель, сохранить защищённые дамп PostgreSQL и копию кода/конфигурации. После установки зависимостей и миграций запустить панель с `TELEGRAM_WORKER_DISABLED=true`. Отдельный российский worker использует ту же БД и конфигурацию прокси с `TELEGRAM_WORKER_DISABLED=false`. Прежний worker выключить из автозапуска, сохранив возможность его вернуть после остановки нового. Два polling-процесса одновременно не запускать.

Миграция 009 включает расписание отчётов, но не включает Telegram-доставку и не привязывает чаты. Уже привязанные получатели сохраняются. Отладочных сообщений сотрудникам не отправлять.

Отмена доступна автору последнего обратимого действия в течение пяти минут: параметры задачи, сдача/приёмка/возврат, запрос и решение согласования, уточнение, ответ на контроль, комментарий. Требует отдельного подтверждения. Новое действие по задаче, изменившиеся правила, небезопасная иерархия или уже начатая внешняя синхронизация блокируют отмену. Создание/удаление задач, настройки и расписания автоматически не отменяются.

Исходные события и решения неизменны; отмена фиксируется отдельным событием. Приёмка восстанавливается связанным техническим экземпляром сдачи, исходный результат не перезаписывается. Новые отчёты исключают отменённые действия из активности, а состояние прошлой даты восстанавливают по всей цепочке. Сохранённые ранее отчёты остаются неизменными. Неотправленные уведомления отзываются; участники получают уточнение об отмене. Старые кнопки бота отзываются.

Контрольная отметка личная для руководителя: начинает новый отсчёт действий, сохраняя сроки и историю. Шуточная рассылка выключена по умолчанию, включается отдельно каждым руководителем, требует подтверждения и ограничена одним разом в час. Получатели — подключённые сотрудники с незавершёнными задачами в области его доступа.

После обновления проверить: health, два входа, отсутствие демонстрационного выбора роли, полный журнал, фильтры согласований, состояние worker и свежий heartbeat без ошибок. Не создавать и не изменять реальные задачи для проверки.
