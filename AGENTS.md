# РУСПЭТ — правила работы

- Прочитай `HANDOFF.md` и актуальные разделы `README.md` перед изменениями.
- Пользователь проверяет интерфейс и бизнес-сценарии сам; агент пишет код, миграции, обработку данных и выполняет необходимые технические проверки.
- Не допускай намеренной загрузки CPU до 100%. Сборки, тесты, сканирование и конвертацию запускай последовательно. Тесты используют один worker (`npm test`). Не используй субагентов для параллельной локальной работы. Перед длительной тяжёлой задачей запроси подтверждение.
- Репозиторий должен оставаться закрытым: `data/first-sheet.json` содержит реальные сведения компании. Не публикуй их в публичные репозитории, логи, примеры и отчёты об ошибках.
- Не коммить `.local/`, `.env`, токены, пароли, сессии, дампы БД. Не выводи секреты в чат или терминал.
- Битрикс24 не подключать без отдельного запроса. Не выдумывать его API. Провайдер сейчас mock.
- Telegram: по запросу владельца от 3 ноября добавлены отдельные привязанные личные чаты и напоминания сотрудникам. Доставка разрешена только привязанным получателям при включённой настройке; отладочные сообщения реальным сотрудникам не отправлять. Не запускать второй polling-процесс того же бота одновременно.
- Данные берутся из первого листа `руспет.xlsx`; реальным задачам не добавлять вымышленную историю. Тестовые фикстуры допустимы только в изолированной тестовой БД.
- Старые переносы GAS хранил в листе `taskIndex`. Его счётчик мог увеличиваться при повторном попадании в отчёт. Не считать его доказанной историей изменений срока. Сейчас нужны исходные `taskIndex`/старые отчёты.
- Обычная работа сотрудников планируется через Telegram. Веб-панель предназначена владельцу проекта и руководителям. Действия обоих интерфейсов должны использовать общие права, версии, историю и правила.
- Результат изменения проверяй по мере необходимости: `npm run check`, `npm test`, `npm run build`. Не изменяй рабочие 497 задач ради тестирования.
