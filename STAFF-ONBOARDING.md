# Подключение сотрудников через /start

Ветка `feature/telegram-staff-onboarding` включает QR-вход и исправление формата Telegram-прокси. Нужна миграция 023 и один обновлённый worker того же выпуска, что панель. Токен бота менять не требуется.

## Загрузить базу

Администратор открывает **Настройки → Знакомство сотрудников с ботом**, выбирает XLSX, нажимает «Проверить файл», проверяет сопоставление и подтверждает загрузку. Нужен оригинальный файл «Копия Почты и номера сотрудников РП и АП.xlsx», который владелец прислал в чате. Он не включён в Git: загрузите его через браузер после обновления.

Читаются листы с колонками «Фамилия, имя», «Отдел», «Номер телефона», корпоративной/табличной почты и Bitrix ID. «Общий список» пропускается, потому что повторяет сотрудников в другом формате. Повторные одинаковые записи объединяются; телефон, email и Bitrix ID сохраняются только в закрытой БД. В предоставленном файле получилось 61 запись, 60 с телефоном; у 46 записей есть номер, не встречающийся у других записей. Это ещё не гарантия автоматического подключения: также нужны совпадение имени и однозначная учётная запись.

Предпросмотр показывает имена, организацию, отдел и результат сопоставления; в журнал импорта попадает только количество. Проверка файла не меняет данные. Подтверждение связано с хешем содержимого и текущего сопоставления. Повторная загрузка обновляет контакты без дублей; отсутствующие записи не удаляются. Импорт добавочный: это не автоматическое увольнение сотрудников и не отзыв ранее выданных доступов. Удаление Telegram-привязки выполняется отдельно в «Доступах сотрудников».

Подтверждённые ранее Bitrix-связи используются для сопоставления вместе с именем; новые связи с порталом не активируются. Однозначные имена связываются с существующими пользователями. Тёзки и неясные совпадения требуют администратора. Роли, задачи, подчинение и существующие Telegram-привязки импорт не меняет. Новые профили создаются при подтверждении регистрации.

## Сценарий сотрудника

1. Открыть `@b_ruspet_bot`, нажать «Старт» или отправить `/start`.
2. Ввести имя и фамилию словами. Порядок допускается любой, регистр и е/ё не мешают сравнению.
3. Нажать **«Поделиться своим номером»**. Telegram передаёт собственный контакт аккаунта; ручной ввод номера не заменяет эту проверку.
4. При уникальном совпадении номера и имени бот связывает числовой Telegram ID с учётной записью. Отправить `/menu` и начать работу. На сайте создать новый QR, подтвердить его в боте и вернуться в браузер.

Telegram username, длинный код и пароль для этого не нужны. Для ранее привязанных пользователей `/start` сразу открывает меню и при отсутствии веб-входа добавляет вход через Telegram/QR. Уже отключённые учётные записи автоматически не включаются.

Для нового профиля назначается только обычная роль сотрудника. Существующие роли сохраняются. Новые аккаунты получают вход через Telegram/QR без действующего пароля; администратор может отдельно нажать «Создать пароль» в «Доступах сотрудников». Пароль показывается ему один раз. Самостоятельный выбор роли, руководителя или существующей чужой учётной записи недоступен.

## Проверка администратором

При общем/отсутствующем/другом рабочем номере, тёзках, занятой учётной записи или отозванной привязке бот создаёт заявку. Сотрудник также может отправить `/manual` после ввода имени либо нажать «Не могу поделиться номером». `/cancel` отменяет попытку. Состояние сохраняется на сервере, заявка действует сутки; не более пяти новых попыток с одного Telegram за сутки.

Администратор нажимает «Обновить заявки», выбирает заявку, сотрудника справочника и, если нужно, конкретную существующую учётную запись. Перед подтверждением проверяет личность через известный рабочий канал и отмечает галочку. Заявку можно отклонить. Новая учётная запись создаётся только по явному выбору/при отсутствии подходящей; отключённая учётная запись и занятый Telegram не перезаписываются. После решения сотрудник отправляет `/start`. Отдельных отладочных рассылок и автоматических сообщений администратору нет.

ФИО используется для поиска, но не служит единственным подтверждением личности. Проверяются личный чат, реальный sender ID и совпадающий `contact.user_id`; чужие и пересланные контакты не принимаются. Другим сотрудникам не показываются совпадения, телефоны и список аккаунтов. Повторное самостоятельное подключение после административного отзыва отправляется на ручную проверку; отзыв нельзя обойти новой командой `/start`.

Привязка использует прежний `users.id`, поэтому существующие права, адресация согласований, напоминания и QR работают через одну учётную запись. Это не заменяет настройку иерархии и подтверждённой синхронизации с Битриксом. Bitrix ID из XLSX сохраняется как исходное поле справочника, а не как автоматически проверенная связь с порталом.

## Обновление VPS

```bash
bash <<'SH'
set -e
cd /root/ruspet-code
GIT_SSH_COMMAND='ssh -i /root/.ssh/ruspet_github -o IdentitiesOnly=yes' \
  git fetch origin feature/telegram-staff-onboarding
git show FETCH_HEAD:scripts/update-server.sh > /root/update-ruspet.sh
RUSPET_UPDATE_BRANCH=feature/telegram-staff-onboarding bash /root/update-ruspet.sh
SH
```

После установки загрузить XLSX в настройках и проверить регистрацию в своём чате. Существующий worker должен использовать body-совместимый транспорт; эту правку ветка уже содержит. Не запускать второй polling-процесс. Рабочая база, реальные чаты и VPS из облачной среды не менялись.
