# Разработка в Codex Cloud

Репозиторий: `CheyMay/ruspet-control`, приватный. Облачная среда на момент подготовки инструкции ещё не создана; запуск на Linux в Codex Cloud пока не проверен.

## Создание среды

В Codex под тем же аккаунтом открыть Settings → Codex Cloud → Environments → Create environment. Выбрать только этот репозиторий, подключив GitHub при необходимости. Оставить доступ к среде личным (Only me). Для установки зависимостей нужен доступ к реестру npm. Не добавлять Telegram-токен, доступ к Битрикс24 или рабочую DATABASE_URL.

Для разговора настройки среды использовать задание:

> Подготовь приватный ruspet-control для разработки. Прочитай AGENTS.md, HANDOFF.md и CLOUD.md. Используй Node.js 24 и отдельную PostgreSQL только внутри этой среды. Последовательно выполни npm ci, npm run check, npm run build. Затем запусти npm run dev: он создаёт локальную БД, применяет миграции и импортирует 497 исходных задач. Сервер слушает 127.0.0.1:4310. Проверь готовность и выполни npm test последовательно, используя отдельные тестовые БД. Не подключай Telegram и Битрикс24, не используй рабочую базу или секреты исходного ПК. Запиши проверенные команды установки и запуска в Install script и Start skill среды. Сохрани приватность предпросмотра, не открывай демонстрационный вход в публичный интернет. Сообщи реальные результаты и оставшиеся ограничения.

После успешной проверки сохранить и опубликовать среду кнопкой Publish. Публикация конфигурации среды не означает публикацию сайта; доступ должен остаться Only me. Для продолжения выбрать Work in → Cloud → эту среду.

## PostgreSQL и Linux

`npm run dev` использует embedded-postgres, если DATABASE_URL отсутствует. Зависимость устанавливает бинарники для текущей ОС через npm; не переносить node_modules и .local с Windows.

PostgreSQL не запускается от root. Если облачная среда работает от root, настройщик должен запускать разработку под непривилегированным пользователем с доступом к папке проекта либо подготовить отдельный PostgreSQL под системным пользователем и передать локальную DATABASE_URL. Не включать создание системного пользователя без понимания окружения и не менять для этого Windows-настройки проекта. Подключение к внешней рабочей БД не является обходным решением.

Тестам нужен доступ к PostgreSQL с правом создавать и удалять собственные тестовые базы. Применять это только к БД разработки. `npm test` уже ограничивает параллельность. Не запускать установку, сборку и тесты одновременно.

## Что хранится и где

- GitHub хранит код, миграции, исходную выгрузку и инструкции. Законченные изменения коммитить и отправлять в GitHub; для отдельных задач использовать отдельные ветки.
- Облачная задача имеет собственные файлы и БД разработки. Новые задачи не следует считать подключёнными к единой изменяемой БД. Реальные ответы, отчёты и решения с домашнего ПК автоматически сюда не попадут.
- Новый импорт восстанавливает начальные 497 задач, а не текущее состояние рабочей базы. Telegram и расписание по умолчанию выключены. Для сценариев бота использовать встроенный предпросмотр.
- Постоянная общая рабочая база, приложение и бот требуют отдельного размещения и резервного копирования. Среду разработки не использовать как постоянный сервер компании.

Для первой задачи после настройки: «Продолжи РУСПЭТ. Прочитай AGENTS.md, HANDOFF.md и CLOUD.md; сверь актуальную ветку. Следующую конкретную доработку сообщу отдельно». Не запускать фоновую разработку без конкретной задачи.

Официальная инструкция: https://learn.chatgpt.com/docs/environments/cloud-environments
