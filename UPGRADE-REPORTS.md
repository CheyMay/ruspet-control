# Отчёты и цена задачи · 3 ноября 2026

Ветка `feature/reports-pricing` включает предыдущий выпуск задач и напоминаний. На VPS изменения автоматически не устанавливаются. Для предыдущего этапа см. [UPGRADE-REMINDERS.md](UPGRADE-REMINDERS.md).

## Поведение

- Цена берётся из поля выгрузки `Цена задачи`, если отдельное значение ещё не сохранено. Ноль — допустимая цена. Категории в рублях: низкобюджетные `< 5 000`, средние `5 000–54 999,99`, высокие `55 000–499 999,99`, премиум `≥ 500 000`. Цена видна в карточках, списке и боте; категории доступны как фильтры, показатели дашборда и отчётов. При создании новой задачи цена обязательна. Отсутствующая цена старой задачи отмечается отдельно и проверкой качества; значения не выдумываются.
- Общий отчёт показывает текущий фронт и закрытия выбранного периода. По умолчанию период начинается в полночь МСК: закрытия прошлых дней в сегодняшнюю сводку не попадают. Незакрытые прошлые просрочки остаются частью текущего фронта.
- Доступны произвольные дата/время, исполнитель, постановщик, автор действий, очередь и категория цены. Для анализа действий сотрудника есть отдельный фильтр «Кто действовал»: принятие чужой работы руководителем не приписывается исполнителю как личное действие. Обычный сотрудник видит собственные задачи; права руководителей сохраняются.
- Сводка содержит время предыдущего сопоставимого отчёта за тот же день, изменение показателей, почасовые закрытия и итоги сотрудников. Подтверждение напоминания не считается обработкой задачи. Полного списка задач в новой сводке нет; числовые показатели открывают сохранённую выборку для работы.
- Фронт каждого сотрудника впервые сохраняется после 09:00 и дальше неизменяем. Вечером сравниваются эти задачи с фактическим результатом: закрыто, осталось, сдано на приёмку, перенесено, добавлено позже. Перенос срока не считается закрытием. Если приложение включили поздно, показывается фактическое время первого снимка. Пропущенные утренние снимки прошлых дней не восстанавливаются.
- Общий автоматический отчёт — в 09:00, вечерние итоги и рекомендации на следующий рабочий день — в 19:01 МСК, пн–пт. После миграции расписание отчётов включено; его можно выключить в панели. Личные сводки Telegram работают при включённых боте и доставке: 09:00, оставшиеся просрочки после 12:00, итоги и завтра после 19:01. Сохраняются подтверждение получения и повторы через 30 минут до истечения текущего сообщения. Праздники пока не учитываются.
- В Telegram — один построчный текст сводки, кликабельные показатели, ссылка на отчёт и кнопка получения PDF-файла. Ссылки ведут на сайт с фильтрами; после обычного входа проверяются права. Токены входа в ссылки не включаются.
- PDF генерируется сервером, содержит встроенные кириллические шрифты и не требует установленного браузера. Печатная версия и CSV сохранены. Старые отчёты остаются неизменными.

## Границы данных

История до импорта отсутствует. Состояние в прошлом восстанавливается только по зарегистрированным событиям; отчёт явно сообщает о неполном покрытии периода или недоступности состояния на выбранную дату. Старые 497 задач и их история не перезаписываются. Повторный импорт исходной выгрузки для обновления не требуется.

Важность по цене не заменяет исходный признак важности. Реальный Bitrix24 по-прежнему не подключён. Обязательное поле будущей интеграции необходимо сопоставить с подтверждённым полем Bitrix при отдельном подключении.

## Обновление двух серверов

1. Сохранить защищённый дамп общей PostgreSQL и резервную копию кода/конфигурации. Получить проверенный коммит `feature/reports-pricing` в отдельной Git-копии. Не заменять рабочую базу выгрузкой, не запускать `db:seed`.
2. Выполнить последовательно `npm ci`, `npm run check`, `GOMAXPROCS=1 npm run build` с Node.js ≥22.12. Новая зависимость `pdfkit` обязательна на панели и worker.
3. Остановить зарубежный `ruspet-bot`, оставить SSH-туннель БД работающим. Перед миграцией остановить `ruspet.service`, чтобы старые процессы не работали одновременно с новой схемой.
4. Обновить полный код панели `/opt/ruspet`: сервер, shared, scripts, web, манифесты/lockfile и dist. Обязательно перенести `server/assets/` вместе со шрифтами и лицензией. Сохранить серверные `.env`, секреты, runtime-файлы и владельца `ruspet`; установить зависимости по lockfile.
5. Под пользователем приложения с тем же окружением БД выполнить `npm run db:migrate`. Нужна миграция `009_reports_pricing.sql`; если предыдущий выпуск не устанавливался, мигратор последовательно применит также `008_reminders.sql`. Миграция 009 добавляет цену, параметры/сводки отчётов, неизменяемые снимки фронта, вечерние уведомления и включает расписание 09:00/19:01. Пароли и задачи не изменяет.
6. Запустить `ruspet.service`; проверить health, вход, фильтр цены, новый отчёт и скачивание PDF. На российском процессе оставить `TELEGRAM_WORKER_DISABLED=true`.
7. Обновить `/opt/ruspet-bot` до того же коммита, включая `server/assets/` и зависимости. Запустить единственный `ruspet-bot`, проверить heartbeat/ошибки. Включение доставки и привязка получателей остаются отдельными настройками; миграция их не включает.

Для отката сохранить новую историю и снимки. Не восстанавливать старый дамп поверх уже внесённых пользователями изменений. Старый код не понимает вечерний тип уведомления: при аварийном откате сначала остановить worker и выключить доставку, затем согласовать совместимость кода и схемы.
