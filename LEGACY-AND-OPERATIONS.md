## Ошибки, которые не переносим

- 3968–3973: перенос увеличивается просто при наличии записи в taskIndex. Новый счётчик меняется только при применении нового срока.
- 4398–4405: исполнители читаются по количеству столбцов, не строк. Новый импорт обрабатывает все 497 записей и 8 исполнителей.
- 4382–4396: повторные отчёты за день конфликтуют, включая скрытые. Новые отчёты имеют ключ день + область доступа + тип; повтор возвращает тот же снимок.
- Листы менеджеров очищаются при повторной раздаче. В новой системе объяснения самостоятельны и не удаляются проверкой.
- `pullExecutorAnswers` получает текст через `getTaskResult`, а не обычные локальные ответы. Реальную интеграцию переписки нужно проектировать отдельно по актуальной документации Битрикс24.
- KPI `completed` записывается как completedCount + sentToAcceptance, хотя часть принятых задач участвует в обоих счётчиках. Нужна проверка семантики до переноса формулы.

## Что изменено в этой итерации

Общая функция разделения очередей для API и UI; прошлые просрочки / срок сегодня / предстоящие / без срока / приёмка / завершённые. Сегодняшние задачи с истёкшим временем отмечены отдельно. «План на сегодня» проверяет пересечение планового интервала и не равен крайнему сроку сегодня.

Добавлены пять типов неизменяемых отчётов: общий, сегодня, прошлые просрочки, приёмка, итоги дня. Итоги показывают события закрытия, переноса, отказа и объяснения, накопленные после импорта. Старые снимки не пересчитываются. Состав отчёта можно раскрыть и выгрузить CSV.

Добавлен локальный планировщик с журналом запусков, блокировкой от параллельного выполнения и максимум тремя попытками одного задания. По включённому администратором расписанию: утром проверки и три очереди-отчёта, днём обработка напоминаний, вечером итоги. По умолчанию выключен. Пн–пт, МСК, только пока сервер запущен. Пропущенные прошлые дни не восстанавливаются искусственными снимками. После позднего запуска утренний снимок будет фактически поздним: время создания сохранено.

Реальный Telegram подключается отдельным личным пилотом: один чат, одноразовая ссылка на 15 минут, команды /status, /today, /overdue. Автоматическая очередь уведомлений пока mock; решения/объяснения через кнопки Telegram и массовая доставка пока не реализованы. Это исключает случайную рассылку реальным сотрудникам на стадии отладки.

## Размещение

Предварительный выбор: основное приложение и PostgreSQL на российском сервере, отдельный процесс Telegram. Сначала проверить исходящее HTTPS-соединение с api.telegram.org с конкретного хоста. Для long polling публичный webhook и туннель не требуются: процесс сам получает обновления через getUpdates. Webhook и polling одновременно не используются. Источник: https://core.telegram.org/bots/api#getupdates.

Если доступ нестабилен: Telegram-процесс на имеющемся зарубежном сервере; он общается с основным API по защищённому каналу. Ему не нужен прямой доступ ко всей PostgreSQL — только узкий API очереди сообщений и входящих действий, отдельная служебная авторизация, идентификаторы операций и повторы. Этот удалённый протокол пока не реализован; нынешний локальный пилот использует ту же БД.

Туннель может быть транспортом между серверами, но сам по себе не решает потерю заданий, повторные решения и недоступность сервисов. Для производства также нужны нормальный вход вместо переключателя ролей, реальные назначения, постоянный процесс/перезапуск, резервное копирование с проверкой восстановления, наблюдение за очередью и обработка сбоев источника. SSH сейчас отсутствует; развёртывание не выполнялось.

## Когда можно считать должность автоматизированной

Нужна проверка полного рабочего дня: источник обновился → проверки закончились → вопросы доставлены → ответы привязаны → руководитель принял решение → изменение применено → итог сохранён → ошибка видна ответственному. Для каждого этапа нужны владелец, срок ожидания, повтор и следующий шаг. Человеческое управленческое решение и ручная оценка не должны подменяться случайным автоматическим разрешением.

Следующий перенос по приоритету: регламент обращений и реальные маршруты; очередь приёмки и возвраты; качество постановки и родители/подзадачи; нагрузка и план следующего дня; KPI после согласования формул. Это ещё работающий пилот, а не полная замена сотрудника.
