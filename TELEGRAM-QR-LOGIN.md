# Вход в панель через Telegram

Ветка `feature/telegram-qr-login` включает предшествующий выпуск первичного импорта Битрикс. Миграция `022_telegram_qr_login.sql` добавляет одноразовые запросы и сведения о способе входа в сессиях. Пароли и роли сотрудников не меняются.

## Подключение сотрудника

Администратор открывает **Настройки → Доступы сотрудников**:

1. У сотрудника должен быть активный персональный вход в панель. Если его нет, нажать «Создать вход».
2. Нажать «Создать приглашение» и лично передать ссылку нужному сотруднику. Она действует 15 минут; получатель открывает бота и нажимает «Старт». Перевыпуск отменяет прежнюю ссылку.
3. В качестве альтернативы нажать «Привязать по ID», ввести проверенный числовой Telegram ID личного аккаунта и подтвердить правильность. `@username` не подходит. Telegram ID — не телефон и не ID сотрудника в Битриксе. Сотрудник всё равно должен открыть бота и нажать «Старт».

Один Telegram связан с одним сотрудником. Переназначение занятого ID отклоняется. Для смены аккаунта сначала отключить старую привязку, затем создать новую. Отключение отменяет ещё действующие запросы, приглашения, старые кнопки рабочего бота и завершает сессии, созданные через эту привязку. Сессии по паролю сохраняются. Список ID доступен только администратору; публичная страница его не раскрывает.

## Как войти

На странице входа нажать **«Показать QR-код»**. Сканировать обычной камерой телефона и открыть Telegram. При необходимости нажать «Старт»: ссылка сразу запускает подтверждение входа. Бот показывает сотрудника, адрес сайта и шестизначный код; его надо сравнить с экраном браузера и нажать **«Подтвердить вход»**. Браузер откроет обычную панель с прежней ролью сотрудника.

На телефоне можно нажать **«Открыть Telegram на этом устройстве»**, подтвердить и вернуться в прежний браузер. Кнопка **«Войти на сайт»** в главном меню бота открывает сайт; отдельного встроенного сканера/Mini App нет.

Код действует 2 минуты. «Обновить QR-код» отменяет предыдущий запрос этого браузера. Бот ничего не разрешает при одном только открытии ссылки: требуется отдельное подтверждение. Отказ, истёкший срок, повторное использование и отсутствие активного входа блокируют выдачу сессии. Привязка и активность учётной записи проверяются при показе подтверждения, решении, выдаче сессии и при последующих запросах сессии Telegram. Новые QR-сессии живут до 12 часов. Выход из системы и успешный вход по паролю отменяют незавершённые QR-запросы этого браузера.

Подтверждать следует только собственный вход. Не пересылать QR-код или ссылку подтверждения другим людям.

## Настройки сервера и обновление

Нужны `DEMO_AUTH=false`, правильный `PUBLIC_ORIGIN=https://cheymay.ru`, включённый личный Telegram-пилот и один работающий polling-worker. Бот должен знать свой username в `telegram_runtime` и успешно опрашивать Telegram в последние 3 минуты без ошибки. При недоступности бота сайт предлагает обычный пароль; секретный токен бота панели для генерации QR не нужен. Токен остаётся только на существующем worker.

Установить одинаковый код панели и существующего Telegram-worker. Скрипт сохраняет включённые службы, делает резервные копии, применяет миграцию и перезапускает их; не создаёт второго worker. Из root-консоли VPS:

```bash
bash <<'SH'
set -e
cd /root/ruspet-code
GIT_SSH_COMMAND='ssh -i /root/.ssh/ruspet_github -o IdentitiesOnly=yes' \
  git fetch origin feature/telegram-qr-login
git show FETCH_HEAD:scripts/update-server.sh > /root/update-ruspet.sh
RUSPET_UPDATE_BRANCH=feature/telegram-qr-login bash /root/update-ruspet.sh
SH
```

Если бот работает на отдельном сервере, его код и БД также должны быть обновлены до совместимой версии до проверки входа. Не запускать второй polling-процесс. При проверке на VPS использовать собственную администраторскую привязку; реальные приглашения сотрудникам выдаёт администратор лично.

## Контракт и защита

- `GET /api/auth/qr/config` — доступность; `POST /api/auth/qr` — новый запрос, локальный SVG и Telegram deep link. QR генерируется локально, внешнего сервиса QR нет.
- `GET /api/auth/qr/:id` — состояние только в исходном браузере; `DELETE` — отмена; `POST /:id/consume` — атомарное однократное создание стандартной сессии после подтверждения.
- QR содержит только отдельный случайный токен подтверждения (`/start login_…`), не пароль, сессионный токен или токен бота. В БД — SHA256 токена и отдельной случайной привязки браузера. Привязка браузера находится в HttpOnly/SameSite=Strict cookie, с Secure при HTTPS; UUID без cookie не даёт даже состояния.
- Подтверждение обрабатывается только в личном чате от совпадающего числового sender ID; группы, отсутствующий/чужой sender и бот-отправитель отвергаются. После открытия запрос закрепляется за этим сотрудником.
- Публичные операции проходят существующую проверку Origin, ответы API — no-store. Создание ограничено 30 запросами в минуту на адрес приложения; за reverse proxy этот бюджет общий для его клиентов. Проверки состояния/выдачи доступны только с секретом браузера.
- Одновременные подтверждения, потребление и изменение привязок сериализованы транзакциями. В журнал входа попадает только открытый ID запроса, без токенов и кода. Запросы старше суток очищаются при создании нового; событие успешного входа остаётся в журнале.
- `PUT /api/system/access/:id/telegram` принимает `{telegramId: string|null, confirmed:true}` только от администратора; `null` отключает привязку. Недействительные/занятые ID и молчаливая замена прежней привязки запрещены.

Проверки используют только отдельную тестовую PostgreSQL, вымышленных сотрудников и поддельный транспорт Telegram. Реальные чаты, рабочая база и VPS в облачной разработке не изменяются.
