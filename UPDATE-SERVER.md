# Обновление сервера из Git с отключённым Битриксом

Рабочая папка `/opt/ruspet` установлена копированием и может не содержать `.git`.
Git-копия хранится отдельно; серверные `.env`, секреты, настройки и данные остаются
на месте. Не выполнять `git init`, `reset --hard`, повторный импорт или `db:seed`
в рабочем приложении.

На сервере от root, при настроенном доступе к закрытому GitHub-репозиторию:

```bash
git clone --branch main https://github.com/CheyMay/ruspet-control.git /opt/ruspet-source
python3 /opt/ruspet-source/scripts/update-server.py --bitrix-disabled
```

Если `/opt/ruspet-source` уже существует как Git-копия, вместо clone выполнить:

```bash
git -C /opt/ruspet-source pull --ff-only origin main &&
python3 /opt/ruspet-source/scripts/update-server.py --bitrix-disabled
```

Нужны Python 3.9+, Git, npm, pg_dump и pg_restore подходящей версии. Поддерживается
локальная PostgreSQL через Unix socket или loopback без TLS, как на этом сервере. Основная
`ruspet.service` должна работать: скрипт читает её фактические окружение,
Node.js, UID/GID и конфигурацию подключения к БД, не печатая секретов.
Сначала в отдельной папке проверяются зависимости, TypeScript и сборка.
Затем приостанавливаются действующие службы этого приложения, создаются
закрытые копии кода/конфигурации и дамп именно его БД под `/root/ruspet-before-*`,
переносятся код/зависимости/сборка и применяются миграции. Перезапускаются только
ранее работавшие панель, Telegram-worker и viewer; проверяется локальный health.
Импорт задач не выполняется. На VPS скрипт должен запускать владелец; из среды
разработки он не запускается против действующего приложения.

Скрипт записывает `/etc/ruspet/bitrix-disabled.env` и подключает его последним
через `zzzz-ruspet-bitrix-off.conf` к обнаруженным службам приложения. Все флаги
синхронизации выключены, ссылки на файлы Bitrix-секретов пусты. Приёмник событий
возвращает 404. Найденные отдельные службы Bitrix не перезапускаются и получают
дополнительный `ConditionPathExists=!/etc/ruspet/bitrix-disabled.env`.
Никаких Bitrix-секретов для этого обновления не нужно.

Для будущего включения интеграции сначала следовать BITRIX-EVENTS.md; затем
удалить созданные `zzzz-ruspet-bitrix-off.conf`, выполнить `systemctl daemon-reload`
и осознанно запустить нужные службы. Не использовать этот вариант обновления,
если требуется сохранить уже включённую синхронизацию.

Если обновление остановилось после приостановки служб, скрипт сохраняет
подготовленную папку и резервные копии. Сначала исправить указанную причину;
не запускать старый код и не восстанавливать БД поверх новых данных автоматически.
