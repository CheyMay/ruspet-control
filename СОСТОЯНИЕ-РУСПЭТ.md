# РУСПЭТ · состояние на 13 ноября 2026

Рабочий адрес `cheymay.ru`. Код в приватном репозитории `CheyMay/ruspet-control`, ветка `pilot/november-13`. Мобильный вход `/mobile`, планер владельца `/time`.

## Что работает

| Часть | Возможности |
| --- | --- |
| Панель | Дашборды, очереди задач, просрочка отдельно от срока сегодня, фильтры, проверки качества, отчёты, PDF и CSV |
| Задачи | Карточка с вкладками, обсуждение, история, приёмка и возврат, перенос срока, черновик копии, пользовательские поля, запрос исполнителя на редактирование, отмена поддерживаемых действий |
| Делегирование | Подбор менеджера клиента по ОКБ или задачам, поручение с приёмкой, автоматическое закрытие исходной задачи после приёмки всех поручений |
| Согласования | Первый этап у руководителя филиала. Руководитель продаж получает второй этап по отметке контроля или коду с буквой «В». Есть уточнения и история решений |
| Сотрудники | Роли, персональные доступы, просмотр от имени сотрудника, заявки на подключение, подтверждение личности через Telegram и вход по QR |
| Telegram и мобильная версия | Личные списки, поиск, карточки, действия по задачам, голосовые команды через Groq, сводки сроков и новых назначений |
| Уведомления | Веб-колокольчик, Telegram, установка мобильной версии на главный экран, фоновые push по подписке на устройстве |
| ОКБ и процессы | Отдельная БД компаний, ответственные, связь задач с клиентом, расписания и сценарии по событиям |

## Где что хранится

- React и TypeScript в `web/`. Express API и фоновые задачи в `server/`. Общие типы и бизнес-правила в `shared/`.
- PostgreSQL хранит задачи, события, решения, сессии и очереди. Основная БД `ruspet_demo`. ОКБ хранится в `ruspet_okb`. Схема меняется миграциями в `server/migrations/`.
- Панель и Telegram используют один код и общие права. Входящие сообщения Telegram принимает одна служба `ruspet-bot-proxy.service`. Транскрибация использует Groq. Для push приложение использует Service Worker и собственные VAPID-ключи.
- Битрикс24 подключается отдельно через REST-клиент и балансировщик. Только активированные связи участвуют в обмене. Инструкция и остаток работ в [БИТРИКС-ПОДКЛЮЧЕНИЕ.md](БИТРИКС-ПОДКЛЮЧЕНИЕ.md).

## Что остаётся

- Контрольный прогон реальных учётных записей, входа с телефона, доставки push и маршрутов на согласованных задачах.
- Установка вебхука и параметров балансировщика, сопоставление ID и контрольный обмен с Битрикс24. Автоматическая постановка новых задач на портале ещё не реализована.
- Чат сотрудников и отделов, фото в сообщениях, транскрибация голосовых чата с хранением только текста. Это отдельный пилот после запуска задач.
